# `dataset_2012-24_new` vs `dataset_2012-26`

Both tables live in `Data/dataset.sqlite`. The earlier Logistic Regression number (0.6409 acc)
was computed on `dataset_2012-24_new`, while the fixed train/test/validation split
(`Data/splits/split_keys.csv`) was cut from `dataset_2012-26`.

## They are the same data, one extended by ~1.5 seasons

| | `dataset_2012-24_new` | `dataset_2012-26` |
|---|---|---|
| Rows (games) | 15,115 | 16,963 (16,969 before the 2024-26 fix) |
| Date range | 2012-11-04 → 2024-04-28 | 2012-11-04 → 2026-01-07 |
| Seasons | 2012-13 … 2023-24 | 2012-13 … 2025-26 (2025-26 through Jan 7) |
| Extra column | — | `index.1` (row index, dropped by every model) |

Games per season are identical for 2012-13 through 2023-24. `dataset_2012-26` adds 1,310 games from
2024-25 and 538 from 2025-26 (1,314 and 540 before the fix; see below).

- Every one of the 15,115 games in `dataset_2012-24_new` is in `dataset_2012-26`, in the same row order.
- On those shared games every feature value is identical, except `index` (a row index both scripts
  drop) and 3 rest-day values (`Days-Rest-Home` ×2, `Days-Rest-Away` ×1).

So this is a naming inconsistency, not two different datasets, **up to 2023-24**.

## The 2024-25 and 2025-26 rows: leaked the outcome, now fixed

The rows only `dataset_2012-26` has were originally built from team snapshots that already included
the game being predicted. The cause was a one-day offset lost in the upstream rewrite of
`Get_Data.py`. That has been fixed at the source and those two seasons' rows regenerated by
`scripts/regenerate_2024_26.py` (see `docs/findings.md` §1).

The regeneration left the 15,115 rows through 2023-24 byte-identical. It rebuilt the later rows as
1,848 games instead of 1,854: six early-season games no longer have a full 30-team pre-game
snapshot. `Tests/test_dataset_leakage.py` now passes for all 14 seasons.

## Is the split still valid?

| Split | Dates | Games in split | Baseline features, after the fix | Pre-game features |
|---|---|---|---|---|
| train | 2012-11-04 → 2022-01-06 | 11,878 | leak-free (never affected) | leak-free |
| test | 2022-01-07 → 2024-11-13 | 3,394 | leak-free; last 152 games regenerated | leak-free |
| validation | 2024-11-13 → 2026-01-07 | 1,697 | leak-free; all regenerated | leak-free |

**Yes, for every model, on the corrected data.** Six split games (4 test, 2 validation) no longer
have a dataset row and drop out of every model equally, along with 23 games missing from the
game logs.

Before the fix, the baseline's validation scores and 156 of its test games were inflated. Those
superseded results are kept in `results/pregame/pre_fix/`.

- **The earlier LR number is not comparable to the split results either way.** The LR script makes
  its own 90/10 split of whatever table it is given, so on `dataset_2012-24_new` its test set is the
  last 1,512 games of that table (2023-24). That is a different set of games from the split's test
  set. Before the fix, running the same script on `dataset_2012-26` gave 0.6889 accuracy, because its
  last 10% fell in the then-leaky 2024-26 period.
